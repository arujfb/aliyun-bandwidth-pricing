## 1M 带宽到底是多快：先学会换算

阿里云公网带宽的换算规则很固定：1M 带宽的下载速度约 128KB/秒，N 兆带宽就是 N 乘以 128KB/秒。

| 带宽 | 单用户跑满时的下载速度 |
| --- | --- |
| 1M | 约 128KB/秒 |
| 2M | 约 256KB/秒 |
| 3M | 约 384KB/秒 |
| 5M | 约 640KB/秒 |
| 10M | 约 1.25MB/秒 |

这个速度是整条管道的总量，要分给所有访客。3M 带宽下，你一个人下载文件最快 384KB/秒；但如果同时有十个访客在打开网站，这条管道就由十个人分摊。假设首页 2MB，没人跟你抢时 5 秒左右能打开，高峰期就会明显变慢——带宽不足的第一表现是网站打开慢，服务器本身并不卡。

估算需要多大带宽，有一个常用的粗略方法：1M 带宽一天大约能支撑 1000 个 IP 的访问量。照这个比例，预估日访问 2000 个 IP 的站点，选 2M~3M 就能应付。

还有一条对几乎所有场景都成立的建议：图片多、有软件下载的网站，靠堆带宽解决不了问题。把静态资源放进对象存储 OSS，再挂一层 CDN，源站带宽压力会小一大截，这笔钱比直接升级带宽划算得多。

## 按固定带宽还是按流量计费：看利用率就够了

判断标准一句话：带宽利用率低于 10%，选按使用流量计费；利用率高且流量稳定，选按固定带宽计费。

两种模式的差别：

- **按固定带宽**：先付费后使用，买 3M 就是恒定 3M，跑多少流量都不另收钱，适合 7×24 小时在线的 Web 服务。
- **按使用流量**：先使用后付费，按实际产生的公网出流量扣费，北京地域约 0.8 元/GB，每小时结算一次。

## 不同业务场景的带宽档位

官方给出的基准线是：入门级云服务器带宽 3M 起步，一般企业选 5M 基本足够，中型网站建议 10M。具体到场景可以这样对应：

- 个人博客、知识分享站，日均几百到几千 PV：1M~3M 够用
- 企业官网、初创公司展示站：3M~5M
- 论坛、内容站、图片较多的站：5M~10M，图片放 OSS
- 有下载或视频播放的站点：小固定带宽加 CDN 分流，下载流量按实际用量另算
- 纯 API 接口、后台管理系统：1M~3M 通常就够，传输的多是文本数据

带宽和 CPU 内存是两条线：带宽决定数据出去得快不快，CPU 和内存决定请求处理得动不动。2核2G 配 3M、2核4G 配 5M 这类活动组合本身就是搭配好的均衡配置，新手照着选不会出大错。

## 几个高频问题

### 3M 带宽真的够吗？

对个人博客和日均几千 PV 的小站来说，够。3M 对应 384KB/秒的管道，配合 CDN 缓存静态资源后，日常访问很难碰到瓶颈。真正吃带宽的是图片站、下载站、视频站这类业务，做这类站之前先规划好 CDN。

### 轻量服务器的 200M 峰值带宽是什么概念？

峰值带宽指最高可达的突发速度，和 ECS 固定带宽那种恒定保证是两回事。38元/年的轻量机型标称 200M 峰值带宽，突发能力很强，但对应的流量规则在下单前建议到活动页的套餐说明里确认清楚，再判断它和 99元档的 3M 固定带宽哪个更适合你的访问模式。

### 按流量计费会不会账单失控？

有余额保护机制：账户余额不足时公网访问会停止，不会无限扣费。真正的风险是欠费导致网站打不开，所以按流量模式更适合有精力盯账户的业务，或者流量波动明显的场景。
